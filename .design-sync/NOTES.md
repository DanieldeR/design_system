# Design System sync notes

- **react_design_system/** is a hand-built visual twin of the Flutter design system at the repo root (`lib/`) — created specifically so this project could sync to claude.ai/design (Flutter can't). Keep tokens/components in visual parity when either side changes.
- No Storybook — `shape: package`. Component discovery comes from `react_design_system/dist/`'s `.d.ts` exports.
- `cssEntry` points at `react_design_system/dist/styles.css`, which is already the fully-bundled stylesheet (tokens + typography + base + every component's CSS, esbuild-bundled from `src/styles/index.css`'s `@import` chain). No separate `tokens/`/`fonts/` dirs to scrape — everything is inlined there, including the two brand webfonts (see below) as base64 `dataurl`s via `build.mjs`'s `.woff2: "dataurl"` esbuild loader. That's why `styles.css` is ~260KB rather than ~16KB — expected, not a bug.
- **2026-07-04 rebrand**: went from a brand-neutral placeholder (generic blue, system fonts) to a real identity — navy + brushed copper + (originally) warm matte-white neutrals, Playfair Display (display/heading) + IBM Plex Sans (body), tighter radii (2/4/6/8px instead of 4/8/12/16). Both font files are OFL-licensed, downloaded from Google Fonts / the `google/fonts` GitHub repo (variable TTFs for Flutter, static-weight woff2 for React) — license texts saved alongside in each package's `fonts/licenses/`. `--ds-color-accent` (copper) is new — wired into Tabs' active indicator and Input/Select's focus border; `--ds-color-brand` (navy) stays on primary actions (buttons, checkboxes, radios). Re-synced via the atomic path (`resync.mjs --remote`) — the diff correctly showed all 17 components' source/props unchanged (only `styles.css`/`README.md` moved), so no re-grading was needed, just a re-upload of styling + the conventions-header-carrying README.
- **2026-07-04 neutrals update**: the warm matte-white neutrals from the rebrand read too vintage-editorial; the user asked for "more modern." Swapped the neutral ramp warm→cool (slate-tinted: `#f7f9fb` … `#080a0d`), and in light mode moved surfaces to pure-white cards (`neutral-0`) on a soft cool-gray page (`neutral-50`) with `neutral-200` borders; dark mode deepened to a near-black navy background (`navy-900`) with `navy-800`/`navy-700` layered surfaces. Navy brand, copper accent, fonts, and radii all unchanged. Same atomic re-sync (styling + README only, no component/grade churn). Applied identically to both packages — conventions.md's color paragraph updated to describe the cool-neutral surfaces (it previously said "warm matte white, never stark #fff", now wrong since surface IS `#fff` in light).
- `overrides.DSModal` and `overrides.DSToastViewport` are set to `cardMode: "single"` because both portal to `document.body` (via `createPortal`) and would otherwise escape their preview card. `DSToastViewport` additionally pins `primaryStory: "Success"` — without it, "single" mode defaults to alphabetically-first export ("Danger"), which is a less canonical representative render.
- Fixed a real component bug found during preview review: `DSCheckbox`, `DSRadio`, `DSTabs`, and `DSCard`'s button variant all used `font-family: inherit` in their CSS. Since `.ds-root` (which sets the base font) only applies inside a `<DSTheme>` wrapper, and CSS import order put these rules after `typography.css`, label text rendered in the browser's default serif font whenever these components' own `ds-text-*` class lost the cascade tie. Fixed by setting `font-family: var(--ds-font-family)` explicitly in all four — same pattern every other component already used. Documented as a "watch for this" pattern in `conventions.md`.

## Re-sync risks
- **No automated render/grade verification has ever run** — Playwright's Chromium isn't installed on this machine, and the user chose to skip the automated path (`--no-render-check`) rather than install ~200MB. All 17 previews were instead manually reviewed by the assistant via direct headless-Chrome screenshots (not through `package-capture.mjs`), which caught and fixed 3 real issues (see above). There are no `.design-sync/.cache/review/*.grade.json` files — a future re-sync has no "carried forward good" grades to rely on and will treat every changed/added component as `pendingGrade` until Playwright is installed and the official capture/grade loop runs at least once.
- If Playwright gets installed later, run `package-validate.mjs` (drop `--no-render-check`) and `package-capture.mjs` once to establish real grades — worth doing before the next content change, so future re-syncs get real anchor-based skips instead of re-reviewing everything by hand again.
- The React package (`react_design_system/`) has no automated visual-parity check against the Flutter package — if either changes, re-verify by eye (both have example/gallery apps that render the full component set).
